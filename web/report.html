01

Executive Overview & Motivation

The explosion of heterogeneous Internet of Things (IoT) endpoints—ranging from resource-limited smart meters and industrial sensors to edge gateways—has drastically widened the modern cyber attack surface. Traditional Network Intrusion Detection Systems (NIDS) rely on centralized telemetry collection, sending raw packet streams to a corporate server or cloud data center for deep inspection and model retraining.

In contemporary IoT deployments, centralized approaches collapse due to three fatal bottlenecks:

  • Privacy & Compliance Violations: Sending raw unencrypted telemetry violates GDPR, HIPAA, and proprietary industrial confidentiality regulations.
  • Bandwidth & Network Congestion: Continuous transmission of multi-gigabyte PCAP/NetFlow captures across cellular or low-bandwidth LPWAN connections is economically and physically unfeasible.
  • Catastrophic Forgetting of Novel Attacks: In dynamic environments, new attack vectors (zero-days, novel ransomware variants, multi-stage botnets) emerge continually. Standard retraining overwrites prior threat signatures.

Project Objective: Building on the foundation of the IEEE TNSM 2026 paper by Carillo et al., this project introduces a Decentralized Adaptive Federated Class-Incremental Learning (FCIL) Framework. Edge nodes train exclusively on local flow telemetry, preserve historical attack knowledge via exemplar rehearsal and knowledge distillation, and transmit only parameterized model updates. The central aggregator dynamically weights each client's contribution based on local data volume, validation score, and communication staleness.

System Architecture & Method of Learning

The framework integrates three collaborative pillars: Federated Learning (FL), Class-Incremental Learning (CIL), and Prototype Classification.

1. High-Level Architectural Flow

Step 1: Edge Sensing
Telemetry Ingestion
IoT gateways passively capture IP packets, parsing headers into 20 normalized numerical telemetry features without inspecting payload content.
Step 2: Local CIL Training
Rehearsal & Distillation
Clients train SimpleNet on local batches combined with an exemplar buffer (200 flows) and a KL-divergence teacher loss from the global model.
Step 3: Central Aggregation
Adaptive Weighting
The central server collects weight tensors and client metadata, calculating normalized non-uniform weights to synthesize the global model.

2. Neural Network Architecture: SimpleNet

Implemented in models/simple_nn.py, the edge model is specifically engineered for sub-millisecond execution on constrained microcontrollers: 

Input Vector (d=20) 
  ──> Linear(20, 64) ──> ReLU 
  ──> Linear(64, 64) ──> ReLU 
  ──> Linear(64, num_classes) ──> Logits Output

Parameter Efficiency: With 20 input flow features and 3 target classes, the total parameter count is strictly: (20 × 64 + 64) + (64 × 64 + 64) + (64 × 3 + 3) = 5,699 parameters. In standard 32-bit floating-point representation, the entire model footprint occupies only 22.3 KB.

3. Overcoming Catastrophic Forgetting

When a new attack class emerges at stage $t$, standard gradient descent drastically degrades performance on prior classes $\{1, \dots, t-1\}$. This system neutralizes catastrophic forgetting through a dual-mechanism approach:

  • Rehearsal Exemplar Memory: Each client preserves a small fixed-capacity memory buffer ($M=200$ samples) containing balanced exemplar representations of historically observed network traffic classes.
  • Knowledge Distillation Loss: During local optimization, the previous round's global model acts as a frozen Teacher Model. The training loss combines supervised classification with distillation:
    $$\mathcal{L}_{total} = (1 - \lambda)\,\mathcal{L}_{CE}(y, \hat{y}) + \lambda\,T^2\,\mathcal{D}_{KL}\left(\sigma\left(\frac{z_{student}}{T}\right) \;\Big\|\; \sigma\left(\frac{z_{teacher}}{T}\right)\right)$$
  • Class Prototype Vectors: Each client computes mean penultimate feature representations per class. The server aggregates these into global centroid vectors, enabling nearest-mean prototype classification during non-linear distribution shifts.
03

Client Partitioning & Federated Training Pipeline

To mirror real-world IoT deployments where different routers monitor distinct physical devices (e.g., smart cameras vs. industrial PLCs), dataset partitioning and round simulation follow a deterministic, reproducible pipeline.

Phase A: Dataset Partitioning (Offline Preprocessing)

Executed via scripts/prepare_data.py:

Partitioning Strategy Distribution Profile Real-World IoT Context
IID Mode (Uniform) Random shuffling, uniform slicing across $K$ clients. Baseline comparison where every gateway experiences identical background and attack frequencies.
Non-IID Mode (Dirichlet $\alpha=0.5$) Probability vector sampled from $\text{Dir}(\alpha \cdot \mathbf{1})$. Severe class imbalance per client. Highly realistic: one edge node encounters DDoS storms, another encounters SQL injection, while others only observe benign telemetry.

Each client partition is written to isolated compressed archives: data/processed/<dataset>/clients/client_i.npz.

Phase B: The Federated Communication Round Loop

When running python experiments/runner.py --dataset "TON_IoT datasets" --rounds 10 --epochs 2 --aggregator adaptive, the following sequence occurs for every round $r \in \{1, \dots, 10\}$:

  1. Model Distribution: The central server broadcasts the current global model weights $W_{global}^{(r)}$ to all participating IoT edge nodes.
  2. Client Local Validation Split: Each client splits its private partition into 80% local training data and 20% held-out validation data.
  3. Local Training (2 Epochs): Clients execute local SGD on the augmented batch (current data + rehearsal exemplars), penalizing divergence with teacher distillation.
  4. Local Quality Assessment: Each client tests its newly updated local model on its held-out 20% validation split, recording validation accuracy ($\text{val\_score}$).
  5. Privacy-Preserving Upload: Clients upload only their model parameter dictionary ($W_i$) and lightweight metadata ($\text{data\_size}$, $\text{val\_score}$, $\text{timestamp}$). Zero raw packet records ever leave the local gateway.
  6. Adaptive Aggregation & Global Checkpoint: The server computes normalized adaptive weights, synthesizes the new global model, logs round statistics, and saves global_model.pt.

The Adaptive Aggregation Formula

Standard federated algorithms like FedAvg weight updates solely by dataset volume ($w_i = \frac{n_i}{N}$). In heterogeneous IoT systems, a compromised or noisy sensor reporting thousands of erroneous samples would dominate the global model, while a high-quality gateway with fewer samples would be ignored.

Our adaptive aggregator (implemented in server/aggregator.py) computes dynamic, non-uniform aggregation weights:

$$w_i = \frac{(\text{data\_size}_i)^\alpha \;\cdot\; (1 + \text{val\_score}_i)^\beta}{1 + \gamma \cdot \text{staleness}_i}$$
Normalized Final Aggregation Weight:
$$\tilde{w}_i = \frac{w_i}{\sum_{j=1}^{K} w_j} \qquad \Longrightarrow \qquad W_{global} = \sum_{i=1}^{K} \tilde{w}_i \cdot W_{local, i}$$
Component Mathematical Term Functional Role & IoT Defense
Sample Volume Term $(\text{data\_size}_i)^\alpha$ Rewards clients with statistically representative data batches, scaling statistical significance.
Validation Quality Term $(1 + \text{val\_score}_i)^\beta$ Directly amplifies updates from edge nodes that achieved high local detection accuracy on held-out validation sets.
Staleness Penalty $(1 + \gamma \cdot \text{staleness}_i)^{-1}$ Penalizes stragglers or delayed edge gateways whose model weights reflect obsolete global training states.

Utility Analysis: Advantages & Limitations

An objective engineering evaluation of where the system delivers high value versus where its assumptions fail in real-world deployments.

Where This System Excels (Advantages)
  • Strict Data Sovereignty & Privacy: Raw packet contents and device network signatures never leave the edge perimeter, satisfying GDPR and NIS2 compliance.
  • Bandwidth-Efficient Aggregation: Transmits only ~114 KB of model weights per round instead of hundreds of megabytes of raw PCAP data.
  • Continuous Zero-Day Adaptation: Dynamically accommodates new threat classes over time without suffering from catastrophic forgetting.
  • Robustness to Client Heterogeneity: The adaptive formulation automatically downweights stragglers, noisy telemetry collectors, and low-accuracy edge nodes.
  • Ultra-Lightweight Edge Footprint: SimpleNet requires under 25 KB of memory, enabling line-rate inspection on inexpensive embedded hardware.
Where It Is Not Useful (Limitations)
  • Encrypted Payload Inspection: Relying exclusively on 20 packet-header flow features prevents detection of stealthy application-layer attacks hidden within TLS 1.3 / HTTPS payloads.
  • Ultra-High-Speed Backbone Networks: Software-based Python/Scapy feature extraction cannot handle 40GbE/100GbE line rates (requires dedicated FPGA/SmartNIC DPDK pipelines).
  • Extreme Flash Constraints (< 64 KB): Participating in training requires a Python/PyTorch runtime (~1 GB disk), excluding bare-metal 8-bit/16-bit microcontrollers from acting as training clients.
  • Vulnerability to Byzantine Attacks: Without gradient clipping or coordinate-wise median filtering, an intentionally malicious client could manipulate validation scores to bias weights.
  • Cold-Start Class Adaptation: When a completely novel attack first hits a single node, that node must collect a minimum sample threshold before it can be effectively aggregated globally.

09

Summary & Future Scope

Summary: This project successfully demonstrates a production-ready blueprint for decentralized, privacy-preserving IoT network security. By combining Adaptive Federated Aggregation with Class-Incremental Learning, the framework resolves the fundamental tension between data privacy, catastrophic forgetting, and non-IID client heterogeneity. The resulting SimpleNet model delivers microsecond inference latencies and a minuscule 22 KB footprint, making it ideal for edge gateways.

Future Roadmap & Recommended Next Steps:

  • Byzantine Defenses: Incorporate coordinate-wise trimmed mean or Byzantine-resilient distance clipping (e.g., Krum / Bulyan) into server/aggregator.py.
  • Microcontroller Quantization: Export the trained PyTorch checkpoint (global_model.pt) into a C-array using TinyEngine or TFLite Micro for native execution on bare-metal ESP32 boards.
  • Hardware Packet Acceleration: Replace Python/Scapy packet reading with eBPF/XDP kernel hooks for real-time line-rate feature extraction on Linux IoT routers.
